How everyone contributes

All members can contribute explanations, screenshots and review comments. Each section has one owner who resolves conflicting edits. Developers supply code details and evidence. Documentation members turn these into clear instructions and explanations. Management tracks owners, deadlines and blockers.

Draft, review, ready

1. Agree one owner, one reviewer and a deadline for each section. Record the task in Jira and link the Working Draft.
2. The owner writes in the shared document. Use comments or Suggesting mode for substantial changes to another person’s section. Keep questions beside the relevant text.
3. Change the Jira task to Review. The reviewer checks accuracy, readability and evidence. Bien’s setup instructions should be tested by someone who did not write them.
4. Resolve review comments. Monika checks consistency and generates the Doxygen output. Watts places the reviewed delivery files in Final Files. Jake checks that agreed tasks are complete.

Where work belongs

Google Docs: overview, design explanation, setup steps and results discussion. Use one Working Draft so everyone sees the latest edits.
Code repository: source code, Doxygen comments, the Doxygen configuration and documentation source files. Put the generated API documentation in the format and location required by the course.
Jira: tasks, owners, deadlines, review status and links. Keep meeting decisions in the team’s agreed wiki or meeting notes and link them from the relevant task.
Screenshots and Test Results: evidence with filenames such as alignment-test-01.png. Record the test conditions and caption in the Working Draft.
Final Files: reviewed versions only. This folder is a preparation area. Submission is a separate action handled by the team.
